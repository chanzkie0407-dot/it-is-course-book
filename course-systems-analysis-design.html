📖 Chapter 1 — What Is the Full Process?

Ano ang buong siklo ng pagbuo ng sistema?

Building software is not just writing code — it is solving problems for people. Here is the complete cycle ♻️

Hindi lamang pagsusulat ng code — ito ay paglutas ng problema para sa iba. Narito ang buong proseso:

1️⃣ Understand → 2️⃣ Plan → 3️⃣ Design → 4️⃣ Build → 5️⃣ Test → 6️⃣ Deploy → 7️⃣ Maintain

Alamin → Magplano → Disenyuhin → Bumuo → Subukan → Ihatid → Panatilihin
  • Analysis — What is actually needed? What is the current problem? Pagsusuri — Ano ba talaga ang kailangan? Ano ang problema sa kasalukuyan?
  • Design — How will it be built? Structure, components, technology? Disenyo — Paano ito gagawin? Anong ayos, bahagi, at teknolohiya ang gagamitin?
  • Implementation — Write the code, build the working system Pagpapatupad — Isulat ang code, itayo ang sistemang gagana
  • Testing — Ensure correctness; verify it works as expected Pagsusuri — Siguraduhing walang mali; gumagana ayon sa inaasahan
  • Deployment & Maintenance — Deliver to users, fix issues, add improvements over time Paghahatid at Pagpapanatili — Ibigay sa gumagamit, ayusin kung may sira, dagdagan kung may bagong kailangan

📖 Chapter 2 — Analysis: Discover Real Needs 🔍

Pagsusuri: Alamin ang tunay na pangangailangan

Talk to the Client:

Pakikipag-usap sa kliyente o gumagamit

Do not stop at the first answer — ask deeply to uncover what truly matters:

Huwag makuntento sa unang sinabi — magtanong nang mas malalim:
  • What do you do now? How? Who is involved? Ano ang ginagawa ninyo sa kasalukuyan? Paano? Sino ang kasangkot?
  • What is the most difficult part? Where do things get stuck? Ano ang pinakamahirap na bahagi? Saan kayo nahihirapan?
  • When the system is ready, what will people do first? Kapag tapos na ang sistema, ano ang unang gagawin ng gumagamit?
  • What is NOT needed? — prevents scope creep Ano ang HINDI kailangan? — para hindi lumaki nang lumaki ang gawain

Write Down Requirements:

Isulat ang mga kahilingan — paghiwalayin ang mahalaga sa dagdag

Separate Must-Have Core Features from Future Nice-to-Haves:

Must-Have (Essential)Future / Extra (If Time Permits)
Add, edit, delete product records Export data to Excel / PDF
Record sales transactions Display income charts & reports
Search and look up entries Send reports via email
Talaan ng produkto • Itala ang benta • Maghanap ng tala | Mag-export • Tsart • Ipadala sa email — sa susunod na bersyon

User Story — From the User's Perspective:

Kwento ng Gumagamit — isulat sa simpleng salita 
As a customer, I want to see product prices
so I know how much I need to pay.

Acceptance Criteria:
 ✅ Name and price are clearly listed
 ✅ Sorted from lowest to highest price
 ✅ Total amount is clearly shown
Bilang mamimili, gusto kong makita ang presyo upang malaman ko ang babayaran — dapat malinaw, nakaayos, at buo ang halaga

📖 Chapter 4 — Plan & Architecture 📐

Plano at Istruktura — paano hahatiin ang gawain

Divide by Responsibility:

Hatiin ayon sa tungkulin — huwag pagsama-samahin sa iisang bahagi

Keep things organized — separate concerns so code stays clean and changeable:

Module / LayerPurpose
Model Classes — Product, Sale, Customer; holds data & business rules
Data Storage Database connection; create, read, update, delete operations
Interface / View What users see — menus, forms, results display
Controller / Manager Connects everything — validates, passes data, controls flow
Modelo — datos at patakaran | Imbakan — pagkonekta at paghaku | Ugnayan — nakikita ng tao | Tagapamahala — nag-uugnay sa lahat

Technology Selection Guidelines:

Paano pumili ng gagamiting kasangkapan
  • ✅ What does the team already know? — don't learn new tools under a deadline Ano na ang alam ng grupo? — huwag subukan ang bago kung may nakatakdang tapusin
  • ✅ What does the client require? — Windows, Android, Web? Ano ang kailangan ng kliyente? — sa kompyuter ba, sa selpon, o sa pahina?
  • ✅ Is it free? — avoids unnecessary cost Libre ba? — para hindi magdagdag ng gastos
  • ✅ Is there support? — active community, examples, documentation May tulong ba? — may komunidad, halimbawa, at malinaw na paliwanag

📖 Chapter 5 — Build in Increments 🔨

Bumuo nang bahagi-bahagi — huwag hintayin ang lahat bago magpakita

Prototype Early & Often:

Gumawa ng simpleng bersyon agad — para makita kung tama ang direksyon

Don't hide your work until "finished" — show early, adjust quickly:

  1. Version 0.1 — can add and view records only Bersyon 0.1 — makapagtala at makatingin lamang
  2. Version 0.5 — basic inputs, calculations, and flow working Bersyon 0.5 — may simpleng pagpili at pagkalkula
  3. Version 1.0 — complete, tested, ready for users Bersyon 1.0 — buo, nasubukan, at maaari nang ibigay

Writing Clean Code:

Paano sumulat ng malinis at madaling intindihin na programa
  • ✅ Clear names: calculateTotal() not doStuff() Malinaw na pangalan — alam agad ang ginagawa
  • ✅ One method = one job — don't mix calculation with display Isang tungkulin bawat paraan — huwag pagsamahin ang pagkuwenta sa pagpapakita
  • ✅ Don't repeat yourself — if used in 3 places, make it shared Iwasan ang pag-uulit — gawing iisang bahagi kung paulit-ulit ang ginagawa
  • ✅ Explain WHY, not WHAT — clear code is its own best documentation Ipaliwanag kung BAKIT ginawa, hindi kung ANO ang ginagawa — malinaw na programa ang pinakamahusay na paliwanag

📖 Chapter 6 — Test: Verify It Works Correctly ✅

Pagsusuri: Siguraduhing tama at ligtas ang lahat

Types of Testing:

Iba't ibang paraan ng pagsusuri
  • Unit Test — Check each piece in isolation; known input → verify expected output Pagsusuri sa Bahagi — subukan ang bawat piraso nang mag-isa
  • Integration Test — Do database and program work together correctly? Pagsusuri sa Pagkakaugnay — gumagana ba nang sabay ang lahat ng bahagi?
  • User Acceptance Test — Let real people try it; if they struggle, the system needs fixing Pagsusuri ng Gumagamit — kung nahihirapan sila, may kailangang baguhin sa atin

Test What Should NOT Happen:

Suriin din ang mga hindi inaasahang pangyayari 
❌ Selling with negative amount → must reject
❌ Searching empty record → must say "not found", not crash
❌ Closing while saving → data must not corrupt or vanish
Tumanggi sa negatibong halaga • Magsabi kung walang nakita • Huwag sirain ang datos kahit biglang isara
⚠️ Important: Testing does NOT prove "zero bugs" — it proves the system behaves correctly for what was tested. Always prepare for the unexpected! Hindi nito mapapatunayang walang mali — kundi gumagana para sa inaasahan. Maghanda palagi sa hindi inaasahan!

📖 Chapter 7 — Deliver & Maintain 📦

Paghahatid at Patuloy na Pagpapanatili

What Goes to the User:

Ano ang ibibigay kasama ng sistema
  • ✅ Working application — not just raw source code Programang gumagana — hindi lamang nakasulat na code
  • ✅ User guide — how to start, use, save, change passwords Gabay sa paggamit — paano buksan, magsimula, mag-imbak, at magbago ng hiyas
  • ✅ Deployment guide — how to install on another computer, how to back up Gabay sa paglilipat — paano ilipat at mag-imbak ng kopya ng datos
  • ✅ Support contact — who to reach, how, and typical response time Sino ang tatawagan — paano at kailan sasagot kung may problema

Maintenance — It Doesn't End at Delivery:

Hindi natatapos ang trabaho sa paghahatid — patuloy ang pag-aalaga

Systems evolve — plan to support them:

  • Fix unforeseen issues reported by users Ayusin ang mga hindi inaasahang pagkakamali
  • Add new features as requirements grow Magdagdag ng kakayahan ayon sa bagong kahilingan
  • Back up data daily — computers can fail! Mag-imbak ng kopya araw-araw — maaaring masira ang kompyuter!

📖 Chapter 8 — Example: Complete Store System 🛒

Halimbawa: Buong Sistema ng Tindahan — mula plano hanggang programa

Putting it all together — structure, rules, storage, and flow:

// ===== MODEL — Data & Rules =====
public class Product {
    private int id;
    private String name;
    private double price;

    public Product(int id, String name, double price) {
        this.id = id;
        this.name = name;
        setPrice(price);
    }

    public void setPrice(double price) {
        if (price >= 0) {
            this.price = price;
        } else {
            throw new IllegalArgumentException("Price cannot be negative");
        }
    }
    // ... getters
}

// ===== DATA LAYER — Database =====
public class ProductDB {
    public static void save(Product p) throws SQLException {
        String sql = "INSERT INTO Product (name, price) VALUES (?, ?)";
        PreparedStatement stmt = connection.prepareStatement(sql);
        stmt.setString(1, p.getName());
        stmt.setDouble(2, p.getPrice());
        stmt.executeUpdate();
    }
}

// ===== APPLICATION FLOW =====
public class StoreApp {
    public static void main(String[] args) {
        Product coffee = new Product(0, "Coffee", 35.00);
        try {
            ProductDB.save(coffee);
            System.out.println("Record saved successfully ✅");
        } catch (Exception e) {
            System.out.println("Error: " + e.getMessage());
        }
    }
}
