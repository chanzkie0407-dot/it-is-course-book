📖 Chapter 1 — What Are Git & GitHub?

Ano ang Git at GitHub?
💻 Git — On Your Computer
• Tracks every change you make
• Saves snapshots of your work
• Lets you go back in time
• Works offline ✅ Nasa sariling computer — gumagana kahit walang internet
🌐 GitHub — On the Internet
• Stores your Git projects online
• Share with anyone instantly
• Collaborate with others safely
• Build your developer portfolio ✅ Nasa internet — ibahagi, makipagtulungan, ipakita sa iba

Simple Analogy

Parang dokumento — ganito ang paghahambing
  • Save → Commit = save a named version I-save na may pangalan
  • Save to cloud → Push = send to GitHub Ipadala sa internet
  • Download from cloud → Pull = get latest version Kunin ang pinakabago mula sa internet
  • Try something risky → Branch = work on a copy, original stays safe Kopyahin — subukan nang walang panganib sa orihinal

📖 Chapter 2 — Install & Setup

I-install at ihanda

Step 1: Install Git

Hakbang 1 — I-install
  1. Go to git-scm.com/downloads
  2. Download for Windows/macOS/Linux
  3. Install → Next → Next → Finish (default settings ✅)
  4. Check: Press Win + R → type cmd → Enter
  5. Type: git --version → see version number ✅

Step 2: Tell Git Who You Are

Hakbang 2 — Sabihin ang iyong pangalan at email 
git config --global user.name "Your Full Name"
git config --global user.email "your@email.com"

Use the SAME email as your GitHub account! ✅ Gamitin ang parehong email sa iyong GitHub account

Check Your Settings

git config --global --list

Shows your name & email — correct? Good to go! 🎉

📖 Chapter 3 — Your First Repository

Ang iyong unang imbakan ng proyekto

A Repo = a project folder tracked by Git. Repo = folder na binabantayan ng Git

Method A — Start Fresh (Local)

Paraan A — Magsimula sa sariling computer
  1. Make folder: MyProject on Desktop
  2. Right-click → Open in Terminal / Git Bash
  3. Type these commands:
# Turn folder into Git repo
git init

# Check what's happening
git status

# Select ALL files to save
git add .

# Save with a note
git commit -m "Initial commit: My first project"

# See history
git log --oneline
💡 Golden Rule: Write CLEAR messages! Instead of "update", write "Add header section" — future YOU will thank you! ✅ Isulat ang malinaw na mensahe — hindi "update", kundi "Anong Binago"

Method B — From GitHub (Clone Existing)

Paraan B — Kopyahin mula sa GitHub
  1. GitHub → New Repository → Name → Create
  2. Copy URL: https://github.com/YourName/YourRepo.git
  3. On your computer:
# Download the whole project
git clone https://github.com/YourName/YourRepo.git

# Enter the folder
cd YourRepo

📖 Chapter 4 — The Daily Workflow

Araw-araw na gawain — ugaliin ito!

Every time you finish changes, follow this — it becomes a habit! 🔄

# 1. Check what changed
git status

# 2. Select files to save
git add index.html
# Or ALL changed files:
git add .

# 3. Save with note
git commit -m "Add contact form"

# 4. Send to GitHub
git push

Before Starting Work — Get Latest

Bago magsimula — kunin ang pinakabago 
# Download what others added
git pull
✅ Daily Routine
Pull ← Work ← Add ← Commit ← Push
Never lose your work again! 💾 Kunin → Magtrabaho → Ihanda → I-save → Ipadala — araw-araw na ugali

📖 Chapter 5 — Branching: Work Safely

Pagsasangay — subukan nang walang panganib

Make a copy to experiment — original stays untouched! 🛡️

# See current branch
git branch

# Create new branch
git branch new-feature

# Switch to it
git checkout new-feature

# Shortcut — create AND switch in one step:
git checkout -b new-feature

# ... edit files safely ...

# Save changes as usual
git add .
git commit -m "Add dark mode toggle"

# Go back to main
git checkout main

# Merge the new work into main
git merge new-feature

# Send combined version to GitHub
git push
💡 Why Branch?
• Test risky ideas without breaking working code
• Multiple tasks at once without mixing
• Collaborate without interfering
• Every professional team uses branches! ✅ Subukan nang walang panganib — lahat ng propesyonal ay ginagamit ito

📖 Chapter 6 — Fixes & Common Scenarios

Pag-aayos — bawiin ang pagkakamali

Undo Changes — Different Situations:

Paano bawiin — depende sa kalagayan 
# Not staged yet → discard changes
git checkout -- index.html

# Staged but NOT committed → unselect
git reset HEAD index.html

# Committed but NOT pushed → undo the commit
git reset --soft HEAD~1

# See everything done (history)
git reflog

Ignore Files — Don't Track These!

Huwag isama — ilagay sa .gitignore

Create file named .gitignore in your project folder:

# Inside .gitignore
*.log          # Log files
node_modules/  # Dependencies folder
.DS_Store      # Mac system files
*.class        # Java compiled files
.settings/     # IDE settings
Ilagay ang mga pangalan ng folder/file na hindi dapat ipadala sa GitHub
